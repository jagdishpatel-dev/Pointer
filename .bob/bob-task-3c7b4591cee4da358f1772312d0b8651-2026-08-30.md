## What was wrong

The error `Import "fastapi" could not be resolved` is a **type-checker configuration problem**, not a code problem. The code in [`main.py`](apps/integration/src/main.py) was correct all along — `fastapi` was already installed in the project's `.venv` (confirmed at `.venv/lib/python3.13/site-packages/fastapi/`).

The root cause: `basedpyright` (and Pyright generally) defaults to the system Python when it can't find a `pyrightconfig.json`. The system Python has no `fastapi`, so the import appears unresolvable even though the virtualenv has it perfectly installed.

## The fix

Created [`apps/integration/pyrightconfig.json`](apps/integration/pyrightconfig.json):

```json
{
  "venvPath": ".",
  "venv": ".venv",
  "pythonVersion": "3.13"
}
```

| Key | Meaning |
|---|---|
| `venvPath` | Directory that *contains* the venv folder (`.` = same dir as the config) |
| `venv` | Name of the venv folder (`.venv`) |
| `pythonVersion` | Tells Pyright which Python stdlib stubs to use |

With this file in place, Pyright locates the virtualenv's `site-packages`, finds `fastapi` there, and resolves the import correctly.
